# الوحدة الثالثة: وحدة الحجوزات والطلب (Booking & Ordering Module)

---

## الوصف

تُعتبر هذه الوحدة هي "قلب النظام" ومصدر الدخل الرئيسي. الغاية منها هي تحويل رغبة العميل إلى حجز مؤكد أو طلب شراء مكتمل. تركز الوحدة على معالجة العمليات الحساسة مثل (التأكد من توفر المصور، منع تداخل المواعيد، ومعالجة المدفوعات المالية). يتم الاعتماد هنا بشكل كبير على "منطق السيرفر" لضمان عدم حدوث أخطاء بشرية أو تقنية في المواعيد أو الأموال.

**تعتمد بشكل مباشر على الوحدة الأولى** (وجود عملاء ومصورين) **والوحدة الثانية** (وجود خدمات وباقات). تم عزلها في وحدة مستقلة لأنها تحتوي على أعقد العمليات البرمجية (منع تداخل المواعيد، والتحقق الآلي، والمعاملات المالية).

## المتطلبات المرتبطة

### المتطلبات الوظيفية (Functional Requirements)

| رمز المتطلب | الوصف | آلية التطبيق |
| :--- | :--- | :--- |
| **FR-C3** | حجز المواعيد والجلسات | Server Actions لاستقبال بيانات الحجز. ربط العميل بالمصور والباقة في جدول `bookings` مع حالة أولية "pending" |
| **FR-C4** | التحقق الآلي من الإتاحة | دالة Supabase RPC `check_photographer_availability` لفحص جدول المواعيد ومنع التداخل |
| **FR-C6** | الدفع الإلكتروني وإصدار الفواتير | تكامل مع Stripe. عند نجاح الدفع يُحدث Webhook حالة الحجز، وتُصدر فاتورة PDF عبر Edge Functions |
| **FR-C8** | إدارة الحجوزات السابقة والحالية | React Query مع Polling لتحديث حالة الحجز لحظياً (من "قيد الانتظار" إلى "مؤكد") |
| **FR-C11** | سجل النشاطات الشخصي | استعراض مفصل للفواتير والحجوزات والطلبات كسجل موحد |
| **FR-A2** | إدارة طلبات الحجز (المدير) | قبول/رفض الحجوزات وتعيين المصورين. Database Triggers لتحديث الإشعارات آلياً |

### متطلبات النظام (System Requirements)

| رمز المتطلب | الوصف | آلية التطبيق |
| :--- | :--- | :--- |
| **SR1** | منع تداخل المواعيد | Database Constraints (قيد فريد) + فهرس `idx_unique_photographer_slot` على مستوى قاعدة البيانات |
| **SR5** | سلامة المعاملات المالية | Database Transactions عبر دالة `complete_order` RPC: (خصم المبلغ + إنقاص المخزون + تسجيل الطلب) كعملية واحدة |

### المتطلبات غير الوظيفية (Non-Functional Requirements)

| رمز المتطلب | الوصف | آلية التطبيق |
| :--- | :--- | :--- |
| **NFR-AR3** | سلامة المعاملات المالية (ACID) | Database Transactions مع Rollback تلقائي عند فشل أي جزء |
| **NFR-ET2** | التحقق اللحظي وأقنعة الإدخال | مكونات Calendar و TimePicker من Shadcn/UI مع Zod Validation لمنع اختيار تاريخ قديم أو وقت خارج ساعات العمل |

## الجداول المتأثرة

| الجدول | نوع التأثير | الوصف |
| :--- | :--- | :--- |
| `bookings` | إنشاء / قراءة / تعديل | **الجدول الأساسي:** إنشاء الحجوزات (FR-C3)، تتبع الحالة (FR-C8)، إدارة الحجوزات (FR-A2) |
| `photographer_unavailability` | قراءة | فحص فترات عدم توفر المصور عند التحقق من الإتاحة (FR-C4) |
| `orders` | إنشاء / قراءة / تعديل | إنشاء طلبات الشراء (FR-C6) |
| `order_items` | إنشاء / قراءة | تفاصيل عناصر الطلب |
| `invoices` | إنشاء / قراءة | إصدار الفواتير (FR-C6) واستعراضها (FR-C11) |
| `products` | تعديل (المخزون) | خصم المخزون عند إتمام طلب شراء (SR5) عبر دالة `complete_order` |
| `cart_items` | قراءة / حذف | قراءة عناصر السلة عند إتمام الشراء، وحذفها بعد الإتمام |
| `notifications` | إنشاء | إرسال إشعارات تلقائية عند تغيير حالة الحجز (عبر Trigger) |
| `services` | قراءة | جلب تفاصيل الخدمة المحجوزة |
| `packages` | قراءة | جلب تفاصيل الباقة المحجوزة |
| `photographers` | قراءة | جلب بيانات المصور للحجز |

## المستخدمون المتفاعلون

| المستخدم | المهام داخل هذه الوحدة |
| :--- | :--- |
| **العميل (Client)** | حجز المواعيد (FR-C3)، التحقق من الإتاحة (FR-C4)، الدفع والفواتير (FR-C6)، تتبع الحجوزات (FR-C8)، سجل النشاطات (FR-C11) |
| **المدير (Administrator)** | إدارة طلبات الحجز: قبول/رفض (FR-A2)، تعيين المصورين، مراقبة الطلبات |
